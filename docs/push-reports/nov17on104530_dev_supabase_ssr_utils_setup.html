1. Executive Objective: Why Was This Push Required?

Next.js App Router applications require a secure, server-side session management model. Unlike legacy single-page apps (SPAs) that store tokens in localStorage (vulnerable to XSS attacks), modern Next.js utilizes encrypted httpOnly cookies synchronized between:

  • Client Components: For reactive user interactions (modals, realtime charts, logout button).
  • Server Components & Server Actions: For high-speed SSR rendering without exposing sensitive credentials.
  • Middleware: For intercepting protected routes and refreshing expired JWT auth tokens in the background before rendering.

This push introduced the official Supabase SSR helper suite in utils/supabase/ and connected root middleware.ts, while supporting both newer NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY and standard NEXT_PUBLIC_SUPABASE_ANON_KEY env variable names.
